AI-Assisted Article Finding — Lab session

ThursdayDay 4
Your First AI-Directed Build

Now it's your turn. Each team is assigned one programming exercise — a real engineering task on the Knowledge Atlas codebase. You will use the same 7-step method Prof Kirsh demonstrated on Tuesday. The AI supplies the domain knowledge (via the panel and the context file). You supply the method.

Start by loading your context file into the AI. Then ask the AI to explain the task back to you. Only then convene the panel.

  • Step 0: Paste your exercise's context file into the AI — this gives it the data schemas and file locations
  • Step 0.5: Ask the AI to explain what the task is about — correct any misunderstandings before proceeding
  • Steps 1–3: Convene panel, write spec, define acceptance tests — all before any code
  • Steps 4–7: Implement, verify, diagnose failures, iterate
Due by end of Thursday

Submit a single document with: panel transcript, spec, all prompts (including failures), AI output, verification results, and two-paragraph reflection.

Phase 3 — Fall Site Debugging
🔬
Phase 3 — Weeks 8–10 · Debugging the Fall COGS 160 site
The last three weeks shift from building to testing. Each team is assigned a section of the Designing_Experiments repository — the Fall COGS 160 experiment-making site being developed in parallel. Teams fork the repo, audit their section by simulating a naïve student walkthrough, fix every resolvable issue, write formal success conditions for each page function, and open a Pull Request with a hand-off report. The goal is a site that a new cohort of Fall students can actually use without instructor hand-holding. Sensor integration and adaptive psych instrument work (Q-sort, IAT) are available as alternatives for interested students.

Grading

Detailed grading rubrics for the track work (Weeks 3–7) and the Fall site debugging (Weeks 8–10) will be posted on this page before those phases begin. The Week 1–2 article-finding work is assessed on completion (20 PDFs submitted by Monday of Week 2; continued submissions through Week 2). Usability notes are assessed on specificity — a generic comment such as "the site was confusing" does not count; a note such as "the Article Propose page does not explain whether uploaded PDFs replace a DOI entry or supplement it" does.
